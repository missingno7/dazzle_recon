# DAZZLE 5.0 matching reconstruction

Goal: readable C (and genuinely necessary assembly) that the original toolchain (believed to be
Borland C++ 3.x) turns back into the bytes of DAZZLE.EXE 5.0 (MicroTronics, 1992). Later: reuse
the recovered algorithms in an SDL3 screensaver. Matching first; no SDL3 work yet.

## Layout

| Path | Contents |
|---|---|
| `assets/` | Original distribution files. **Immutable.** Hashes in `evidence/originals.json`. Binaries are not committed. |
| `reference/` | Derived binaries (unpacked EXE, load image). Not committed; regenerated by `tools/`. |
| `src/`, `include/`, `asm/` | Reconstructed source. Single integrator writes here. |
| `tools/` | Small Python scripts (unpacker, map, compile wrapper, compare, status). |
| `evidence/` | Machine-readable evidence: oracle lock, function map, classifications, accepted matches. |
| `docs/` | Short technical findings. |
| `build/` | Scratch, ignored. Workers use `build/workers/<name>/` only. |

## Rules

- Never modify `assets/`. Never derive expected bytes from a candidate build.
- Strict levels: `EXACT` (all bytes of the full extent equal, relocations bound to the same
  targets), `RELOCATED` (instruction bytes equal, relocation targets verified equal after address
  normalization), `SEMANTIC` (behaviour shown, bytes differ), `PROVISIONAL`, `UNKNOWN`.
  Never report SEMANTIC or masked/prefix/similar results as matches.
- No machine code byte blobs (`db`, `__emit__`, inline byte arrays) standing in for compiled code.
  Hand-written assembly is legitimate only where evidence shows the original was assembly.
- Runtime-library (Borland RTL) code is identified, not decompiled. Keep its coverage separate
  from DAZZLE application coverage.
- Record negative results (hypothesis, exact toolchain/flags, outcome) in the relevant doc.
- Workers: write only inside your assigned paths (usually `build/workers/<name>/` plus files the
  brief names). Do not commit. Do not edit `AGENTS.md`, `evidence/accepted*.json` or other
  workers' files. Do not leave background processes (DOSBox-X, servers) running.
- Use Python with `-I` when reading untrusted downloaded files. Keep scripts small; do not build
  queues, databases or dashboards.
- Line endings: keep the existing style of a file (LF for scripts and source unless noted).

## Reference behaviour facts

- `reference/DAZZLE_U.EXE` (unpacked) fails DAZZLE's on-disk CRC check and exits 100; run it with `/I`.
  The CRC covers the MZ extent in front of the tail; `tools/build.py` appends a tail whose CRC is computed
  for the rebuilt unpacked MZ, so `build/DAZZLE.EXE` passes without `/I` (docs/architecture.md "Integrity check").
- Acceptance target is the unpacked program: load image + relocations (tools/link.py) and the regenerated tail.
  Re-packing with PKLITE is out of scope (project decision 2026-10-29); docs/packing.md is background only.
- `/Z` extracts DAZZLE.DOC from the appended LZH tail and exits.

## Commands

- Strict gate (link + every function and TU receipt, ~10 s): `python -B -I tools/check.py` (regenerates
  evidence/match and docs/PROGRESS.md; `--scratch` writes receipts to build/check/, `--link-only` is fastest).
- Rename identifiers everywhere (sources + evidence/bindings): `python -B -I tools/rename.py MAP.json [--dry-run]`.
- Per-function verifier metadata (address, size, symbol bindings) lives in `evidence/bindings/<source>.json`.
- Build runnable unpacked EXE: `python -B -I tools/build.py` -> `build/DAZZLE.EXE` (strict link plus generated self-check tail).
- Unpack (reference): `python -I tools/unpack_pklite.py` -> reference/DAZZLE_U.EXE, load_image.bin.
- Disassemble: `python tools/disasm.py SSSS:OOOO --func`.
- Function level, whole file: `python -I tools/objcmp.py FILE.c --all [--prelude P.c] [--out evidence/match/X.json]`
  (single: `objcmp.py FILE.c FUNC SSSS:OOOO`; add `--fresh` for acceptance).
- Assembly: `python -I tools/asmcmp.py asm/dvdt.asm --all` (TASM 3.0 /ml /m2).
- Translation unit (whole code segment): `python -I tools/segcmp.py PARA FILE.c [FILE2.c ...] --out evidence/match/seg-PARA.json`;
  assembly: `asmcmp.py asm/dvdt.asm --segment 1899 --start 1899:0006 --end 1899:1574`.
- Progress (authoritative, module extents): `python -B -I tools/progress.py` -> docs/PROGRESS.md.
- Detailed inventory status: `python -B -I tools/status.py` -> docs/STATUS.md (its byte columns sum overlapping heuristic inventory spans; use PROGRESS.md for byte totals).

Proven TU-level modules: 066A/DZLE (main + Alt images), 0B84/DZL2 (Ctrl images), 0CCD/DZFD (fades), 11C1/DOSI (startup and program logic), 158D/menu (interactive menus; original name unknown), 17F5/DLOGO (logo), 1899/DVDT (TASM), 19F0/DAZPCX, and 1A72/DHUF. Project headers in include/ are staged automatically: `dazzle.h` (shared declarations; its extern order fixes BSS layout) and `dzconst.h` (shared `#define` constants only). Globals are documented in docs/globals.md; each function has a header comment ending in its original address and size.
