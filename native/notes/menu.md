# Menu port notes

- `toggle_menu_mode`, `render_menu_text`, `draw_framed_box`, `menu_error_message`: original BIOS mode 3 and B800 word accesses are represented by `dz_video_set_mode` and explicit `[row][column][character, attribute]` cell reads/writes. This keeps the menu memory model defined on the native host.
- `menu_error_message`: the reconstructed source indexes a declared `[3][78]` backup with absolute rows 22 through 24. The native version indexes rows 0 through 2 and restores those same screen rows. This removes out-of-bounds access; ask for a DOS-reference check to confirm the recovered binary's actual buffer behavior.
- `check_any_image_configured`: the reconstructed source indexes Ctrl sizes as `index - alt_image_count - 1`, which reads one entry before the Ctrl table at its first element. Native indexes with `index - alt_image_count` to check the intended table entry. This avoids an invalid read; ask for a DOS-reference check to confirm whether the original binary exhibits the apparent off-by-one.
- `configuration_screen` and `help_screen`: the Milestone A `poll_graphics_keys` drains every key already queued. The menu now checks abort state at configuration boundaries and consumes one key in the help wait so scripted and fast sequential navigation keys remain available to the next editor. This preserves interactive menu flow with the native keyboard queue.
- `enumerate_directory_entries`, `configuration_directory_menu`, `select_directory_drive`, `file_access_menu`: DOS `findfirst/findnext`, `getcwd`, `chdir`, and `setdisk` use Win32 file enumeration and the Windows CRT current-directory/drive functions. The native 14-byte entry path uses a Windows 8.3 alias when available and skips names longer than 12 characters when no alias exists, matching the DOS-sized record.
- `append_directory_entry`: the original requests 18 bytes because the DOS node has a 4-byte pointer and 14-byte path. Native uses `sizeof(struct node)` because its pointer is 8 bytes; retaining 18 would under-allocate the node.
- `file_access_menu`: the original delegates serialization and parsing to DOSI functions, which remain pending in this slice. Menu-local native helpers read and write the same `#`, `~`, `^`, fade, and `$` records so File Access works independently; consolidate them with the DOSI port when that module lands.
- `menu_parse_unsigned`: the original scans `%u` into a 16-bit Borland `unsigned`. The native version parses to a 32-bit temporary and narrows only after checking the 16-bit range, avoiding the 4-byte `scanf` write into a 2-byte object.
- `configuration_directory_menu`, `file_access_menu`, `menu_merge_name`, `append_directory_entry`: DOS-sized concatenations and copies are capacity checked on the native host. Directory titles may truncate when a Windows path is longer than the DOS display buffer; overlong file paths fail safely instead of overrunning a buffer.
- `edit_auto_customization`: `auto_fade_pause_ticks` is unsigned storage overlaid as a signed 16-bit `auto_pause` by the original. Native helpers recover its signed word value before division and preserve 16-bit wrap when assigning the seconds-to-ticks product.
- `conio.c`, `text.c`, and `video.c`: console text uses 1-based Borland windows, window-local scrolling, non-translated LF output, the 8-bit blink attribute, absolute `gettext/puttext` rectangles, and normal/solid/hidden cursor shapes. `video.c` reads the cursor scanline range so the two visible cursor shapes render correctly.

- Integration (supervisor): File Access now calls the DOSI reject_exec_filename, load_configuration_file and
  save_configuration_file as the original does; the temporary menu-local copies were removed after the DOSI merge.
